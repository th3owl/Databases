2. PROMETHEUS
============================================================

Prometheus is the metrics collector.

It runs on:

  observer

Container port:

  9090

Browser URL:

  http://192.168.56.20:9090

Important config file:

  /root/monitoring/prometheus/prometheus.yml

Important config:

  global:
    scrape_interval: 15s
    evaluation_interval: 15s

  scrape_configs:
    - job_name: 'postgresql'
      static_configs:
        - targets: ['192.168.56.16:9187']

    - job_name: 'node_exporter'
      static_configs:
        - targets: ['192.168.56.16:9100']

What this means:

  Every 15 seconds, Prometheus connects to:

    192.168.56.16:9187
      postgres_exporter on postgres-server

    192.168.56.16:9100
      node_exporter on postgres-server

  Prometheus pulls metrics from these endpoints and stores them locally
  inside the Prometheus Docker volume.

Prometheus is not reading PostgreSQL log files.
Prometheus is not pushing data.
Prometheus scrapes/pulls metrics from HTTP /metrics endpoints.

Examples of metrics:

  pg_up
  pg_stat_activity_count
  node_cpu_seconds_total
  node_memory_*
  node_filesystem_*

Useful URLs:

  http://192.168.56.20:9090/targets
    Shows whether scrape targets are UP or DOWN.

  http://192.168.56.20:9090/query
    Prometheus query UI.

Useful Prometheus queries:

  up
  pg_up

3. POSTGRES_EXPORTER
============================================================

postgres_exporter runs on:

  postgres-server

Port:

  9187

Metrics URL:

  http://192.168.56.16:9187/metrics

Config file:

  /etc/postgres_exporter.env

Config:

  DATA_SOURCE_NAME="postgresql://exporter:exporter_password@localhost:5432/postgres?sslmode=disable"

What this means:

  postgres_exporter logs into the local PostgreSQL database using:

    user: exporter
    password: exporter_password
    database: postgres
    host: localhost
    port: 5432

  It reads PostgreSQL status/statistics views and exposes them as
  Prometheus metrics on port 9187.

The exporter user was created with:

  CREATE USER exporter WITH PASSWORD 'exporter_password';
  GRANT pg_monitor TO exporter;

Why pg_monitor:

  pg_monitor lets the exporter read PostgreSQL monitoring views without
  using a superuser account.

Health check:

  curl -s http://localhost:9187/metrics | grep '^pg_up'

Expected:

  pg_up 1

5. LOKI
============================================================

Loki is the log storage and log query engine.

It runs on:

  observer

Container port:

  3100

Health URL:

  http://192.168.56.20:3100/ready

Important point:

  Loki does not scrape PostgreSQL logs by itself.

In this lab:

  Alloy reads logs on postgres-server.
  Alloy pushes those logs to Loki.
  Loki stores them and makes them queryable.

Loki push endpoint:

  http://192.168.56.20:3100/loki/api/v1/push

This endpoint is used by Alloy.
You do not manually browse this URL in Chrome.

Why http://192.168.56.20:3100 shows 404:

  Loki does not serve a homepage at /.
  A 404 at / is normal.
  Use /ready for health.

Useful Loki checks:

  curl http://192.168.56.20:3100/ready

  curl "http://192.168.56.20:3100/loki/api/v1/labels"

Expected labels after Alloy is working:

  filename
  host
  job
  level
  service_name
  unit

Query PostgreSQL logs:

  curl -G "http://192.168.56.20:3100/loki/api/v1/query_range" \
    --data-urlencode 'query={job="postgresql"}' \
    --data-urlencode 'limit=20' \
    --data-urlencode 'since=30m'

Query systemd logs:

  curl -G "http://192.168.56.20:3100/loki/api/v1/query_range" \
    --data-urlencode 'query={job="systemd"}' \
    --data-urlencode 'limit=20' \
    --data-urlencode 'since=30m'

6. GRAFANA ALLOY
============================================================

Grafana Alloy runs on:

  postgres-server

Local health port:

  12345

Health check:

  curl -s http://127.0.0.1:12345/-/healthy

Expected:

  All Alloy components are healthy.

Config file:

  /etc/alloy/config.alloy

What Alloy does in this lab:

  1. Reads PostgreSQL log files.
  2. Reads systemd journal logs.
  3. Adds useful labels such as job and host.
  4. Pushes logs to Loki on observer.

PostgreSQL log source block:

  loki.source.file "postgresql" {
    targets = [{
      __path__ = "/var/lib/pgsql/16/data/log/postgresql-*.log",
      job      = "postgresql",
      host     = "postgres-server",
    }]

    forward_to    = [loki.write.monitoring.receiver]
    tail_from_end = true

    file_match {
      enabled     = true
      sync_period = "10s"
    }
  }

What this means:

  Alloy reads files matching:

    /var/lib/pgsql/16/data/log/postgresql-*.log

  It labels those log lines as:

    job="postgresql"
    host="postgres-server"

  It forwards the logs to loki.write.monitoring.

Systemd journal source block:

  loki.source.journal "systemd" {
    forward_to    = [loki.write.monitoring.receiver]
    relabel_rules = loki.relabel.journal.rules
    max_age       = "12h"
    labels        = { job = "systemd", host = "postgres-server" }
  }

What this means:

  Alloy reads systemd journal logs from postgres-server.
  It sends them to Loki.
  It labels them as:

    job="systemd"
    host="postgres-server"

Loki destination block:

  loki.write "monitoring" {
    endpoint {
      url = "http://192.168.56.20:3100/loki/api/v1/push"
    }
  }

What this means:

  All log entries collected by Alloy are pushed to Loki on observer.

Important permission note:

  PostgreSQL log files are owned by postgres and may be mode 600.
  Alloy needs ACL permissions to read them.

Working ACL commands:

  setfacl -m u:alloy:--x /var/lib/pgsql /var/lib/pgsql/16 /var/lib/pgsql/16/data
  setfacl -m u:alloy:r-x /var/lib/pgsql/16/data/log
  setfacl -d -m u:alloy:r-x /var/lib/pgsql/16/data/log
  setfacl -m u:alloy:r /var/lib/pgsql/16/data/log/postgresql-*.log
  setfacl -d -m u:alloy:r /var/lib/pgsql/16/data/log

8. ALERTMANAGER
============================================================

Alertmanager runs on:

  observer

Container port:

  9093

Browser URL:

  http://192.168.56.20:9093

What it does:

  Prometheus evaluates alert rules.
  When a rule fires, Prometheus sends the alert to Alertmanager.
  Alertmanager displays and manages the alert state.

Prometheus alerting config:

  alerting:
    alertmanagers:
      - static_configs:
          - targets:
              - alertmanager:9093

What this means:

  Prometheus sends alerts to the alertmanager Docker service on port 9093.

Current alert rules:

  PostgreSQLDown:
    expr: pg_up == 0

  InstanceDown:
    expr: up == 0

============================================================
10. END-TO-END FLOW SUMMARY
============================================================

Metrics flow:

  PostgreSQL
    -> postgres_exporter on postgres-server:9187
    -> Prometheus on observer
    -> Grafana dashboard/query

OS metrics flow:

  postgres-server Linux OS
    -> node_exporter on postgres-server:9100
    -> Prometheus on observer
    -> Grafana dashboard/query

PostgreSQL logs flow:

  /var/lib/pgsql/16/data/log/postgresql-*.log
    -> Alloy on postgres-server
    -> Loki on observer:3100
    -> Grafana Explore

Systemd logs flow:

  systemd journal on postgres-server
    -> Alloy on postgres-server
    -> Loki on observer:3100
    -> Grafana Explore

Alert flow:

  Prometheus alert rules
    -> Alertmanager
    -> Alertmanager UI

Administration flow:

  pgAdmin on observer
    -> PostgreSQL on postgres-server:5432
